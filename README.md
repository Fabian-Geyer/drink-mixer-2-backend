# drink-mixer-2-backend

This repository will house the backend functionality for a drink mixer developed in my free time.
This software allows the user to define drink recipes, change the current machine setup and status and order the correct drink based on availability.

## Running the backend

### Without Docker

Install [uv](https://docs.astral.sh/uv/), then from the repo root:

```bash
uv sync
uv run alembic upgrade head
uv run uvicorn coma2.main:app --host 0.0.0.0 --port 5055
```

Interactive API docs are served at `/docs` (Swagger UI) and `/redoc`.

### With Docker

```bash
docker compose up
```

## For developers

### Testing endpoints with Swagger UI

There's no Postman collection - the backend serves interactive API docs at
[`/docs`](http://localhost:5055/docs) (Swagger UI) once it's running. To try an
endpoint:

1. Expand it and click **"Try it out"**.
2. For `POST`/`PUT`/`PATCH` requests, edit the pre-filled JSON body.
3. Click **"Execute"** to send the request against your running instance and see
   the actual response.

A read-only alternative (no "try it out") is served at `/redoc`.

### Running tests

```bash
uv run pytest
```

Tests spin up an isolated in-memory SQLite database per test (see
`tests/conftest.py`), so they don't touch your local `coma2.db`.

### Linting, formatting, and type-checking

```bash
uv run ruff check .
uv run ruff format .
uv run mypy coma2 tests
```

All of the above, plus the test suite and a Docker build, run in CI on every
push and pull request (`.github/workflows/ci.yml`).

### Database migrations

Schema changes go through Alembic rather than editing `coma2.db` directly:

```bash
uv run alembic revision --autogenerate -m "describe the change"
uv run alembic upgrade head
```

Review autogenerated migrations before committing them - Alembic doesn't catch
everything (e.g. column renames show up as a drop + add).

### Seeding sample data

```bash
uv run python -m coma2.seed
```

Inserts a few sample ingredients, cocktails, and empty slots. Safe to run more
than once - it only inserts if the relevant tables are still empty.

### Project layout

Each resource is a self-contained module under `coma2/<feature>/`:

```
coma2/<feature>/
  router.py   # FastAPI routes
  models.py   # SQLAlchemy models
  schemas.py  # Pydantic request/response models
```

`coma2/main.py` wires the routers together; `coma2/database.py` and
`coma2/config.py` hold the shared DB session and settings.

## Database

This project uses a simple SQLite Database as the data is straightforward.
The following tables are used:

### cocktail

| Column Name | Data Type | Constraints |
|:------------|:----------|:------------|
| id          | INTEGER   | NOT NULL, PK|
| timestamp   | DATETIME  | NOT NULL    |
| name        | VARCHAR   |             |

### ingredient

| Column Name      | Data Type | Constraints    |
|:-----------------|:----------|:---------------|
| id               | INTEGER   | NOT NULL, PK   |
| timestamp        | DATETIME  | NOT NULL       |
| name             | VARCHAR   |                |
| alcohol_percentage| INTEGER  |                |

### slot

| Column Name       | Data Type | Constraints    |
|:------------------|:----------|:---------------|
| id                | INTEGER   | NOT NULL, PK   |
| ingredient_id     | INTEGER   |                |
| amount_percentage | INTEGER   |                |

### cocktail_ingredient

| Column Name   | Data Type | Constraints    |
|:--------------|:----------|:---------------|
| cocktail_id   | INTEGER   | NOT NULL, PK   |
| ingredient_id | INTEGER   | NOT NULL, PK   |
| amount        | INTEGER   |                |

(PK: Primary Key)

### Relationships

- `cocktail_ingredient` has a foreign key referencing `ingredient(id)`
- `cocktail_ingredient` has a foreign key referencing `cocktail(id)`
