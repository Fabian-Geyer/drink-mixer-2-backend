This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Backend for a physical cocktail-mixing machine ("CocktailMachine V2" / coma2), running on a Raspberry Pi. It's a small FastAPI + SQLAlchemy REST API backed by SQLite (being rewritten in place from an earlier Flask version — see "Ongoing refactor" below). Clients define drink recipes (cocktails), ingredients, and dispenser "slots" (the machine's physical ports, each loaded with one ingredient), and the API is used to check which cocktails can currently be made given what's loaded in the slots.

## Running the backend

**This section describes the pre-refactor Flask app; it is being replaced in place on `refactor-codebase`. See "Ongoing refactor" below for the current state.**

Without Docker:

```bash
uv sync
uv run alembic upgrade head
uv run uvicorn coma2.main:app --host 0.0.0.0 --port 5055
```

Interactive API docs (auto-generated by FastAPI) are served at `/docs` and `/redoc`.

With Docker: `docker-compose up` (builds from `Dockerfile`, maps port 5055, persists `/data` as a named volume — the sqlite db lives at `/data/coma2.db` in the container).

Lint/type-check/test: `uv run ruff check .`, `uv run mypy coma2`, `uv run pytest`.

## Database

SQLite. DB URL comes from `coma2.config.settings.database_url` (a `pydantic-settings` `Settings` object, default `sqlite:///coma2.db`, overridable via `DATABASE_URL` env var or `.env`). In the Docker image it's pinned to `/data/coma2.db` so it persists on the mounted volume. Schema is managed by Alembic (`alembic/`, config in `alembic.ini`) — `uv run alembic upgrade head` applies migrations; `uv run alembic revision --autogenerate -m "..."` generates a new one from model changes.

As of this writing, `alembic/env.py` is wired up but there are no model-backed migrations yet and no seed script — both land alongside the first feature module (see "Ongoing refactor").

Core tables (unchanged conceptually from the pre-refactor schema, see `README.md` for column detail):
- `cocktail` — id, timestamp, name
- `ingredient` — id, timestamp, name, alcohol_percentage
- `cocktail_ingredient` — many-to-many join table between cocktail and ingredient, with an `amount` column (composite PK of both foreign keys)
- `slot` — id, ingredient_id, amount_percentage — represents a physical dispenser slot on the machine and which ingredient (if any) is currently loaded into it. `ingredient_id = 0` means the slot is empty/unassigned (not a real FK relationship — there is no ingredient with id 0).

## Architecture

`coma2/main.py` is the FastAPI app instance and composition root (replaces the old Flask `app`/blueprint setup) — feature routers get included here as they're built. `coma2/config.py` holds the `pydantic-settings` `Settings` object. `coma2/database.py` holds the SQLAlchemy 2.0 engine, `SessionLocal`, `Base`, and the `get_db` FastAPI dependency.

Feature modules still live one-per-folder under `coma2/<feature>/`, being rebuilt as FastAPI routers rather than Flask blueprints:
```
coma2/<feature>/
  router.py   # FastAPI APIRouter, one route function per operation
  models.py   # SQLAlchemy 2.0 ORM model(s)
  schemas.py  # Pydantic request/response models
```

**Mid-refactor state:** `coma2/cocktails/`, `coma2/ingredients/`, `coma2/slots/` currently only contain empty `__init__.py` files — their Flask `routes.py`/`models.py` were removed and not yet replaced. `coma2/main.py` only exposes `/api/health`. See `docs/refactor-requirements.md` for the target behavior of each module (including intentional fixes to gaps in the old implementation) before rebuilding them.

API docs are auto-generated by FastAPI from routes + Pydantic schemas, served at `/docs` (Swagger UI) and `/redoc` — there is no hand-maintained OpenAPI file anymore. The Postman collection at `coma2-backend.postman_collection.json` predates the refactor and needs review once the API surface is rebuilt.

## Working conventions on this branch

- Commit in small, logical units (one coherent change per commit), using Conventional Commits messages (`feat:`, `fix:`, `chore:`, `refactor:`, `test:`).
- Commit locally as you go; do not push until asked.
- Pause for review at each major checkpoint (e.g. after scaffolding, after each module) rather than running through the whole plan unattended.
